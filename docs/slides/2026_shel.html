Overview

Overview

Problem

  • How to measure morphological productivity and changes in morphological productivity over time?
  • Traditional use of hapax legomenon as a proxy has known limitiations (sensitive to corpus size, most data is discarded, etc.) (Pankratz et al. 2022, 2025; Feltgen 2025; Baayen 2008).
  • Automatic segmentation is challenging (Baayen et al. 2011).

Overview

Solution

  • Train a model that can reliably segment large corpora accurately and effeciently.
  • Create a Python package to orchestrate processing and segmentation.
  • Use segmentation as an analytic bridge between raw token data and productivity measures.

Development

Model and model training

  • Base model: ByT5-small, fine-tuned for English morphological segmentation.
  • Task formulation: word in, segmented morpheme string out.
  • Why byte-level modeling:
    • avoids dependence on a fixed subword vocabulary
    • handles orthographic variation, apostrophes, doubled letters, and low-frequency forms more naturally
    • remains open-vocabulary, which matters for historical and uncommon lexical items
  • Why seq2seq generation rather than token classification: generating the segmented string directly is more natural than predicting a label for each character and reconstructing the output afterward.
  • Main tradeoff: byte-level modeling is slower than subword approaches, so caching and batching support in the package matters.

Development

Package architecture

  • The package is organized in layers, from low-level inference to high-level analysis.
  • At the base: a parser that segments words, and a cache that stores results so large corpora don’t have to be re-parsed from scratch.
  • Above that: a decomposition layer that can break complex morpheme strings into their constituent parts. The depth of decomposition is adjustable — useful because different research questions call for different levels of morphological detail.
  • At the top: a productivity layer that turns segmented tokens into analysis-ready tables, and a higher-level analyzer that handles the full workflow end-to-end.
  • The analyzer also integrates with spaCy: token processing can draw on spaCy’s POS tags and morphological attributes, and the model’s segmentation output can be checked against spaCy’s own morph analysis. This provides a practical validation layer and allows the two sources of morphological information to complement each other.
  • The package also ships with curated internal resources — affix metadata, decomposition maps, a protected monomorpheme list — so it works out of the box without external configuration.

Development

Key choices and affordances

  • The package is built around token-frequency input rather than around one corpus-processing stack.
  • The core install is analysis-focused, while prep and audit workflows are optional.
  • Caching is treated as part of the design, not as an afterthought.
  • Multiple decomposition strategies are exposed because different research questions want different levels of morphological depth.
  • Role labels are inferred from supporting evidence rather than treated as fixed truths.
  • The main affordances are:
    • quick single-word inspection
    • batch parsing for corpus inventories
    • reusable cached parsing
    • productivity summaries over time
    • support tables that move from abstract measures back to example words and bases
    • a higher-level analyzer workflow for researchers who do not want to wire the entire pipeline by hand

Development

Current development status

  • The project now includes a reusable package, not just a trained model.
  • Core modules are in place for parsing, caching, decomposition, analyzer workflows, productivity summaries, affix metadata, and matrix transforms.
  • Optional prep modules exist for auditing training data and rebuilding package resources.
  • Versioned resources are already bundled with the library.
  • The codebase has broad automated test coverage across parser behavior, productivity logic, decomposition, caching, affix resources, and corpus preprocessing.
  • The package is still pre-release, but it is already usable as a research workflow.

Example

Table values

  • N: total token count contributed by this morpheme in the preview sample.
  • V: number of distinct word types containing the morpheme in this final-segment slice.
  • V1: number of hapax types, i.e. types that occur once in the sample.
  • F, Y, I: diversity and productivity summaries. Read them comparatively across rows rather than as standalone verdicts.
  • P baayen: hapax-based productivity, useful for asking whether a suffix appears to be recruiting new types in the sample.
  • S baayen: expansion potential relative to the observed vocabulary in the sample.
  • H and H norm: entropy-based dispersion measures that help distinguish concentrated rows from rows spread across many types.
  • dominant morpheme family, dominant morpheme function, and dominant role confidence: the current best role label inferred from the supporting token evidence.
